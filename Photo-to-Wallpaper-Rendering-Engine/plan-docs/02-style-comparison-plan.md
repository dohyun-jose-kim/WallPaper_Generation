# 2단계 스타일 비교 계획

> 현재 실행 범위(2026-11-11): [Build and Compare 0.0.1](build-n-compare-0.0.1/README.md). 세로·가로 2장, 도구 5개, 총 54개 케이스이며 실패도 유지한다. 아래는 이전 조사/환경 기록이다. 10개·26개 제안, Miniforge 대안 및 이전 실행 순서는 현재 범위에 적용하지 않는다.

**상태: 계획 — 실험 조합은 제안이며 실행 결과가 아니다.**

> 2026-11-10 후보 선정 업데이트: [종합 조사](03-renderer-shortlist-research.md)에 따라 medfa12/liquid-glass-react, ybouane/liquidglass, rdev/liquid-glass-react의 동적 3개와 Pillow+NumPy, libvips+pyvips의 정적 2개를 최종 비교 후보로 삼는다. 동적 구현은 정적 프레임 저장과 향후 동적 활용을 함께 평가한다. 아래 26개 조합은 이전 제안이며 실제 조합·결과 수는 이 다섯 후보의 실행 가능성에 맞춰 조정한다.

Brave 기본 새 탭에 사용할 1920×1080 정적 배경을 비교한다. 원본 전체를 중앙에 배치하고 화면 가로와 세로의 90% 이내로 제한한다. 원본은 선명하게 유지하고 남는 여백을 처리한다. 생성형 아웃페인팅은 이번 범위에서 제외한다.

## 실험 범위

세로 사진과 가로 사진 각 1장을 공통 입력으로 사용한다. 확대 블러, 가장자리 확장, 반사 확장과 경계 혼합, 갤러리 여백, 다층 블러·변위·색조·하이라이트를 조합한 유리 효과를 비교한다. 유리 효과는 세 가지 수치 조합을 우선 시도한다. 모든 조합을 모든 도구로 구현한다고 가정하지 않고, 지원 여부와 구현에 필요한 작업을 기록한다. 첫 평가 후 대표 사진 6장으로 확대한다.

새롭게 조사한 [효과 원리와 예시](01-techniques-and-examples.md)의 내용을 실험 설계와 보고서에 반영한다. Pillow + NumPy, libvips/pyvips, ImageMagick의 연산을 같은 입력과 출력 조건에서 비교하고, 문서에 정리된 외부 패딩 사례와 두 웹 셰이더 사례도 각각 검토한다. 각 사례의 실행 가능성, 직접 실행 여부와 결과를 보고서에 남긴다. 실행하지 않았다면 그 이유와 확인 범위를 기록한다. 외부 코드와 자산을 사용할 때는 각각의 라이선스를 확인한다.

필요하면 비교에 사용할 별도의 **Codex 자체 구현 엔진**을 추가할 수 있다. 이 엔진은 Codex가 이 프로젝트를 위해 작성하는 로컬 렌더링 구현을 뜻하며, 사용한 알고리즘과 의존성을 기록해 다른 방식과 같은 조건으로 평가한다.

## 초기 실험 조합 제안

| 방식 | 우선 비교할 구현 | 사진 2장 기준 제안 결과 수 |
| --- | --- | ---: |
| 확대 블러 | Pillow + NumPy, libvips/pyvips, ImageMagick | 6 |
| 가장자리 확장 + 블러 | 위 세 구현 | 6 |
| 반사 확장 + 블러 및 경계 혼합 | 위 세 구현 | 6 |
| 갤러리 여백 | Pillow + NumPy | 2 |
| 유리 효과 3종 | Pillow + NumPy를 우선 사용하고 굴절·블러·색조 등의 강도를 달리함 | 6 |

위 기본 제안은 **총 26개 결과**다. 같은 방식의 도구별 설정을 가능한 한 맞추되 연산 차이와 한계를 기록한다. 이후 libvips/pyvips·ImageMagick의 유리 구현, 외부 패딩·셰이더 사례의 직접 실행, 필요 시 Codex 자체 구현 엔진을 추가 조합으로 평가한다. 추가 결과 수는 실행 가능성과 구현 범위를 확인한 뒤 정한다. 사례별 실행이 어렵거나 비교 조건을 맞출 수 없으면 결과 수에 포함하지 않고 이유를 보고서에 남긴다.

원본 배치의 반올림과 업스케일 정책을 실험 전에 정하고 기록한다. 출력 크기, 원본 영역의 비율과 픽셀 변화, EXIF 방향과 색상 프로파일, 경계 이음새, 파라미터, JPEG/PNG 및 Brave 표시, 재현성, 실행 시간과 최대 메모리를 확인한다. 동일한 조건에서 측정하고 도구별 차이와 측정 한계를 기록한다.

## 공통 실행 환경

기존 uv 기반 `.venv` 하나를 Python 실험에 공유한다. Pillow, NumPy, pyvips는 프로젝트의 [requirements.txt](../requirements.txt)에서 관리하며, 필요성이 확인된 Python 의존성은 여기에 추가한다. 현재 항목은 버전이 고정되지 않은 출발점이다. 설치 후 실제 Python 및 패키지 버전과 uv의 잠금 또는 고정된 의존성 기록을 남겨 재현성을 확보한다. 기존 환경의 Python 3.9.6과 각 패키지의 호환성은 설치 시 확인하며, 필요하면 공통 환경의 Python 버전을 조정한다.

pyvips에는 네이티브 libvips가 필요하며, 현재 공식 안내의 `pyvips[binary]` 번들 또는 별도 설치 중 환경에 맞는 경로를 검증한다. ImageMagick은 Python 패키지가 아닌 별도 실행 도구다. 웹 셰이더는 브라우저와 필요한 실행 도구를 별도로 기록한다. 각 도구와 네이티브 라이브러리의 버전, 설치 방법, 실행 명령 및 운영체제 정보를 실험 기록에 남긴다. 의존성 충돌이나 재현성 문제가 실제로 발생하면 그때 해당 도구만 별도 환경으로 분리한다. 이 계획은 패키지 설치나 렌더링을 완료했다는 뜻이 아니다.

## HTML 보고서와 산출물

`plan-docs/style-comparison-0.0.1/index.html`에 로컬 브라우저에서 열 수 있는 비교 보고서를 만든다. 원본과 결과를 나란히 보여 주고, 방식·도구·설정, 시각적 차이와 경계 품질, 실행 시간·최대 메모리, 구현 난이도 및 미검증 항목을 기록한다. 결과 이미지와 재현 스크립트, 입력 식별 정보 및 실행 기록을 함께 보관하고 보고서에서 상대경로로 연결한다. 원본 사진의 저장과 공유 범위는 선정 시 확인한다.

## 미확정 사항

사진 선정, 효과별 수치, 정확한 실험 조합, 스크립트 인터페이스와 최종 도구 선택은 실험 과정에서 정한다. 이 문서는 사진 선정이나 렌더링 구현을 승인하는 기록이 아니다.
